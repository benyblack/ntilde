# OSC 133 benchmark layer (extensions.osc133-a, -b, -c, -d)

This is the contract behind the [2026-11-11 OSC 133 qualification](2026-11-11-osc133-qualification.md). It qualifies four pinned terminfo.dev@4.0.0 cases
through the App's existing read-only pane-metadata and session-status observations ([owned-metadata.md](owned-metadata.md),
[owned-pane-metadata-api.md](owned-pane-metadata-api.md)). It adds no production API and changes no production behavior: it newly qualifies existing
behavior. It reuses the paired observer of the frozen metadata suite (its 13 experiments, 46 frames and v8 receipt keep their meaning) under its own
`shi` prefix, plan and baseline.

## What the pinned probes actually are

Read from `terminfo.dev@4.0.0` (`terminfo.bundle.mjs`, SHA-256 `aa5f2bf9…d1f6`), not inferred from the names:

| Case | Pinned termless code | Pinned terminal code | Pinned verdict |
|---|---|---|---|
| `extensions.osc133-a` | feeds `ESC ] 133;A BEL X`, reads cell (0,0), `promptConsumptionResult(char === "X")` | writes `ESC[1;1H ESC[2K`, then `ESC ] 133;A BEL X`, asks for the cursor position, `promptConsumptionResult(col === 2)` | inconclusive by design |
| `extensions.osc133-b` | the same with `133;B` | the same with `133;B` | inconclusive by design |
| `extensions.osc133-c` | the same with `133;C` (no payload) | the same with `133;C` | inconclusive by design |
| `extensions.osc133-d` | the same with `133;D;0` | the same with `133;D;0` | inconclusive by design |

`promptConsumptionResult` always returns `pass: false` with outcome `inconclusive`, evidence `consumed` and the note "Marker was consumed; shell prompt
integration was not observed". The acceptance criterion of all four cases is therefore only marker consumption, and it never decides. The pinned verdicts
are preserved, never rewritten. The roles the task names (prompt start, command-input start, command execution start, command completion) are qualified
by separately identified **effect contracts** (`ntilde-osc133-shell-lifecycle-effect-v1`) that are not attributed to the pinned probes. A difference is a
recorded `pinned-inconclusive-by-design` divergence.

The pinned code is retained and executed: a digest-checked derivation (`ntilde-owned-osc133-grading-v1`, layered over the left/right-margin one like its sibling layers)
refuses unless the retained bundle still contains the four registrations (termless **and** terminal functions) and `promptConsumptionResult` verbatim and
once, then only appends exports. The worker runs both paths over the journaled stock-context read: the termless path reads cell (0,0) of the observed screen,
the terminal path asks for the cursor position the observed screen reports. The parent re-executes the termless probes from the retained journal and the
independent model of both paths must agree with the live results.

## The lifecycle the effect contract grades

From the OSC 133 description (FinalTerm; [Contour](https://contour-terminal.org/vt-extensions/osc-133-shell-integration/)) and the repository's own parser
documentation (`AnsiParser.ShellIntegration.cs`), a prompt cycle is `A` (prompt start), `B` (prompt end: the command line begins at the cursor), `C`
(command accepted; an optional payload names the command) and `D` (command finished; an optional exit payload). The independent oracle
(`osc133-contracts.mjs`) interprets every experiment's exact bytes over this lifecycle and predicts the whole screen, the cursor and five lifecycle facts.
Each lifecycle fact is tagged:

- **certain**: the marker's documented semantics determine it, so it is graded.
- **uncertain**: the marker leaves it unspecified (what A does to the window and anchors of an unterminated command; where C places the output anchor
  after the cursor jumped above the input line; any field after a duplicate or out-of-order marker; a non-base64 C payload). The oracle carries the prior
  value forward as an *implementation-policy prediction*, which is recorded beside the observation and never decides a verdict.

| Marker | Documented effect (certain) | Left unspecified (policy, recorded only) |
|---|---|---|
| A | session at its prompt (precise), no current command | window and anchors of an unterminated command |
| B | input window opens; command-start anchor = cursor at the marker; status and command unchanged | a B while a command runs |
| C | window closes; session running; payload (base64 of UTF-8) names the command, a bare C names none; command-start anchor survives; output anchor = row after the input line, column 0, when the cursor is still on the B line | output anchor after a cursor jump; a second C; attribute (`aid=7`) and plain-text payload readings |
| D | window closes; both anchors dropped; session back at its prompt; no current command | the exit payload (never interpreted here) |

Raw anchors are read under the documented coordinate convention: zero-based viewport row and column on the main screen, `absoluteRow` equal to the row
(no history yet), the current history generation, never the alternate screen. An anchor in another coordinate space never matches.

## Experiments

Thirty-two experiments, each starting from the same stage bytes (a completed `D;0` then `A`, title, cwd, a run nonce on row 9 so the pinned
`ESC[1;1H ESC[2K` can never erase it, and a runtime palette override withdrawn at the end). Forty-six reads, inside the observer's 64-capture ceiling.

| Role | Meaning |
|---|---|
| `stock` | the exact pinned fixture on the prepared baseline; its read is the pinned replay's source |
| `effect` | a measured prior state (`prior`), the pinned bytes **without the marker** (`ordinary`, a no-op control), then the exact pinned fixture (`pinned`) |
| `required` | a canonical sequence graded in full: B's prompt/input boundary and consecutive cycles; C's payload identity (the typed text and the payload differ) and output anchor; consecutive cycles for C and D |
| `gate` | each other marker, emitted from the same prior state, must not produce the case's target transition |
| `disclosure` | A's shared status observable with D (D also returns a running session to its prompt): disclosed, never required |
| `observed` | ST (`ESC \`) terminator variants, C payload shapes (`aid=7` attribute, plain text) and the D exit payload (`D;7`): recorded, never graded |

Target transitions: A, a running session at its prompt with no current command; B, an open input window with an anchor; C, a running session with the
window closed; D, a prompt with both anchors dropped and the window closed. A case is **supported** when every required read matches the oracle and the
target transition is shown by the pinned fixture; **unsupported** when a required read mismatches while every validity control held; **inconclusive** when a
control failed (the measured prior state, the unmarked bytes, or a gate). Labels never grade. A stable wrong state is evidence: nothing waits for an
expected state to appear.

## Exit status

The pinned D fixture carries `D;0`, and the criterion is consumption only, so exit-status interpretation is outside the graded claim. The suite sends
`D;7` separately and records what the observations expose: the session status's `exitCode` is the **child process** exit code (set only when the
process exits) and stays null; the snapshot and metadata carry no command exit status. The `commandFinished` event stream, which carries the payload, is
not read here, and PR #709 (which names the finished command on those events) is neither modified nor depended on.

## Boundaries

These fixtures qualify protocol handling in a disposable direct-local App. They do not establish that Bash, Zsh, Fish, PowerShell or any other shell emits
the markers correctly, nor remote (SSH, mux) delivery, Windows or Linux behavior, OSC 133 P, OSC 633, the aggregate `extensions.semantic-prompts` case,
command-assist behavior or the mouse/focus-mode reset that A performs. Cleanup is exactly what the observation API can show: the suite restores the
**prepared** title/cwd baseline (the original null metadata is not observable), the initial cells and the original palette, and every attempt requires the
disposable App and worker to exit.

## Grading, receipt and tests

`osc133-grading.mjs` re-derives every report from the retained paired journal and the worker's run log; `osc133-receipt.mjs` binds it (receipt schema 44,
source policy v38) and refuses any retained byte that no longer rederives, including a typed unavailable record (the owned metadata API or the grid
refused the first observation). Portable tests cover the oracle, wrong transitions, stale anchors, boundary coordinates one column off, command/output
confusion, cross-case substitution, malformed observations, identity mismatch, tampering and incomplete restoration; synthetic fixtures are test-only.
The frozen real-App publication is the evidence.
