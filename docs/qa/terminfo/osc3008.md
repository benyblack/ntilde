# OSC 3008 hierarchical context signalling (#997)

Authority: [UAPI.15 *OSC 3008: Hierarchical Context Signalling*, version 1.0](https://uapi-group.org/specifications/specs/osc_context/) (the systemd.io copy has moved there). The pinned `terminfo.dev@4.0.0` probe `extensions.osc3008-context` is a different, much smaller thing and is kept separate from everything below.

## The pinned probe

One path, no termless function: the terminal path writes `ESC[1;1H ESC[2K`, then `ESC]3008;type=test BEL`, asks for the cursor position and returns `unmeasuredCellResult(pos, "OSC 3008 systemd context")`. That helper always returns `pass: false`, outcome `inconclusive`, so **the pinned verdict can never be anything else**: it is preserved as the conclusion and no score changes. The payload is not a UAPI.15 sequence at all (it has neither `start=` nor `end=`), so a conforming terminal ignores it; the suite measures that as a negative control. Missing evidence is not a demonstrated terminal failure.

## What the App does

`AnsiParser.ContextSignalling.cs` parses `OSC 3008 ; start=<id> [; field=value]... ST` and `OSC 3008 ; end=<id> [; field=value]... ST` (BEL also terminates) and keeps, per pane:

- a **stack of at most 16 open contexts**, outermost first, the last being the active one;
- a ring of the **8 most recently ended contexts** with their valid end metadata.

Both are **untrusted descriptive data written by whatever controls the terminal**. They are observable metadata only: nothing executes, changes the working directory, feeds command assist or reaches an AI prompt, and the App draws nothing from them (no breadcrumbs, tinting, kill or new-shell actions). OSC 133/633 prompt metadata neither creates nor updates a context, and a context never changes the title, OSC 7 working directory, hyperlinks or shell marks. The sequence has no reply.

### Specified behavior (UAPI.15)

| Rule | Source |
|---|---|
| A start opens a context that becomes active; the previous one becomes its parent. | Semantics |
| A repeated start of an open id updates it: its old metadata is flushed, the new fields apply and every sub-context is implicitly ended. | Semantics |
| An id is 1 to 64 printable ASCII characters (32..126), counted after unescaping. | Semantics, ABNF `CTXID` |
| `;` and `\` inside values must be written `\x3b` and `\x5c`; any other backslash is invalid. | General Syntax |
| `type` is one of boot, container, vm, elevate, chpriv, subcontext, remote, shell, command, app, service, session; text fields are 1 to 255 characters (`cmdline` may be empty); `machineid`/`bootid` are 32 to 36 hex digits or hyphens; `pid`/`pidfdid` are 1 to 20 digits that fit an unsigned 64-bit integer. | Metadata Fields, ABNF |
| An end carries `exit` (success, failure, crash, interrupt), `status` (0..255) and `signal` (a symbolic name). | Metadata Fields, ABNF |
| Invalid fields are ignored and the rest used; unknown fields are ignored; field order is free. | Processing, Limits, Security |
| Over-long data is dropped and, once the stack limit is hit, the earlier contexts are kept and the later ones discarded. | Processing, Limits, Security |
| Terminal reset sequences do not affect the stack. A TTY hangup resets it fully. | Processing, Limits, Security |

### Recorded implementation policy (the specification is silent or leaves a choice)

These are compared by the measurement but never decide a verdict.

- The sequence is selected only by the exact first fields `start=` and `end=`; the numbers of the limits (depth 16, ring 8, payload 16,384 characters, 32 fields) are ours: the specification recommends limits without naming any.
- Over-long fields are discarded, not truncated; a malformed id ignores the whole sequence.
- A repeated field keeps its last valid value; a field's "context types" column is descriptive and is not enforced.
- Ending a context also ends its sub-contexts (the specification states this only for an update).
- `status` is limited to 0..255 and `signal` to `SIG` plus up to 16 upper-case letters, digits or `+`.
- **Hangup** is modelled as the end of the pane's child process (`HandleSessionExit`). RIS and DECSTR do not clear the stack. A state-transfer import (mux attach, replay) replaces the target's stack with the source's, validated against the same bounds.

## Observation

`readPaneMetadata` carries `buffer.contexts` = `{untrusted: true, stack: [...], ended: [...]}` (omitted only when the parser is unavailable). `untrusted` is a structural reminder: no value is verified. The contexts are not counted against the 32,768-code-unit metadata budget (the parser bounds them), so a program cannot make the rest of the observation unavailable by filling them. Stored contexts are not a rendering, notification, taskbar or host claim.

## The qualification contract

`ntilde-osc3008-context-effect-v1` is a separately identified effect contract, graded by an independent oracle in `scripts/terminfo/osc3008-contracts.mjs` that is written from the specification text above and never calls the production parser. It reads paired complete screen, pane-metadata and session-status observations (the OSC 133 metadata fixture) at 37 points. Experiment roles:

- **stock**: the pinned fixture bytes on the measured baseline: no context may appear.
- **required** (decided by the specification): minimal start/end, the specification's container example, nesting with an update that flushes metadata and ends sub-contexts, BEL and ST terminators, the 64/65-character id bound and invalid ids, field validity (unknown/invalid/over-long/ABNF-bound fields, escapes), end metadata (the newest ended record), and a soft reset leaving the stack alone.
- **control** (a negative that must change nothing): the pinned payload and foreign spellings (`start`, `begin=`, `START=`, an empty body, an end of an unknown id, OSC 3007, 30080, `133;start`, `633;start`), and a context carrying `cwd=`/`comm=` beside OSC 133 A/B/C/D, which must neither move the title, working directory or shell state nor be created or changed by them.
- **policy**: end-ends-sub-contexts, the depth bound, repeated fields and a bare backslash.

Validity controls: every read exposes the contexts (otherwise the effect is *inconclusive*, never *unsupported*), the bound baseline is empty and every complete screen, cursor, title, working directory, palette and shell state equals the model of the stripped feeds. A valid control set plus a required mismatch is *unsupported*. The pinned verdict stays inconclusive regardless, so every result is a recorded **divergence** between the pinned and effect outcomes, not a stock or common-harness score.

Contexts cannot be cleared by any reset, so each experiment closes what it opens and the oracle replays the whole feed history. At the end the stack is empty again; **the ended ring cannot be cleared and keeps its last records** (the original, empty contexts are not restored byte for byte). The initial null title and working directory are likewise not restorable.

## Limits

Measured: a disposable direct-local App on the measured platform. Not measured: hangup (the suite cannot end the child of its own pane; unit tests cover it), RIS, alternate-screen switches, real emitters (systemd `run0`, `systemd-nspawn`, `machinectl`, shells), remote or mux delivery, other platforms, any presentation of the data, and the 16-deep stack beyond the recorded policy group. A real emitter's field set (the first seven fields of UAPI.15) is exercised only through the specification example.
