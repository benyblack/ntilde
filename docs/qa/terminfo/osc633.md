# OSC 633 A–D lifecycle observation contract

The pinned `terminfo.dev@4.0.0` probes `extensions.osc633-a`, `-b`, `-c` and `-d` feed `OSC 633;A`, `B`, `C` and `D;0` respectively, terminated by BEL and followed by `X`. Their termless paths read cell (0,0); their terminal paths first home the cursor and erase the line, then query the cursor. Both paths call `promptConsumptionResult`, which always returns an inconclusive verdict. The source-pinned adapter exposes these unchanged functions and the parent replays their results from the owned journal.

The separately identified `ntilde-osc633-shell-lifecycle-effect-v1` contract observes a disposable App pane. The [VS Code protocol](https://code.visualstudio.com/docs/terminal/shell-integration#_supported-escape-sequences) defines A as prompt start, B as prompt end, C as pre-execution and D as execution finished, with an optional exit code. This contract examines the App's existing prompt status, input window and command/output anchors as bounded readbacks of those transitions. They are App observations, not protocol-mandated representations.

Each case has an exact stock-context fixture and a separately measured prior state. OSC 133 constructs that prior state and provides a positive control for the observer; OSC 633 is the target and is never replaced in the measured fixture. An unmarked control checks the same printable bytes and cursor preparation, while other OSC 633 markers gate the target transition. A and D may both return to the prompt and A may clear the anchors, so these comparisons are recorded separately rather than treated as negative controls. ST-terminated variants and D without an exit code and with exit code 7 are retained as observations, not part of the graded BEL fixture.

The parent checks complete paired screen, pane metadata and session status snapshots, exact feeds, barriers, identity and restoration. A validity-control failure makes the effect inconclusive; only a valid control set permits a failed target to produce an unsupported effect conclusion. The independently named effect outcome does not change the pinned outcome or the stock collector's score. `exitCode` in session status is the child process exit code, not a command exit code; this observer does not establish interpretation of D's payload.

These experiments are limited to a disposable direct-local App on the measured platform and configuration. They do not establish real shell emission, remote or mux delivery, OSC 633 E/P, command-assist behavior, or command-finished event payloads. The suite restores the initial screen and palette and the prepared title/cwd baseline; original null metadata is not observable and is not claimed as restored.

## Scoped collection

The optional `--scope osc633` selection keeps the existing five-minute owned-run deadline and every per-request, ownership, observation and cleanup limit. It skips only the separate OSC 9 and OSC 777/99 notification suites; their fixed toast waits otherwise cannot fit in the full run's remaining time. The stock collector and all other owned suites remain in the fresh run. The result is explicitly a **scoped** receipt, not a fresh full-suite run.

The scope binds a SHA-256-pinned prior complete owned archive. Before App launch and again while finalizing the new receipt, the current validators extract that archive under bounded, traversal-safe rules and independently reissue its complete receipt, including the omitted predecessor suites. The old run's outcomes and identity remain separate from the fresh observations. The parent rejects notification-suite requests under this scope, and the receipt refuses partial omitted-suite artifacts, changed scope or predecessor bytes, missing target evidence, and unverified cleanup. A normal invocation without `--scope` retains its full-run selection and receipt requirements.
