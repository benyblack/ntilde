The separately identified `ntilde-owned-selection-colors-graded-v1` contract measures what the pinned fixtures cannot. Selection colors are runtime session state, so each experiment starts from a pristine private theme and may only finish when the original state, theme and render return. For every stage it binds four layers to one model: the exact DA-fenced query replies, the App's resolved colors and override flags, the whole render theme (including the derived selection paints), and a controlled offscreen render sampled from the original PNG with the render-only synthetic selection `(2,4)..(4,10)`; the real UI selection is never touched. The set cases show a null reply in the default state, the newest value (never a stale one) after two distinguishable overrides in both BEL and ST spelling, a changed render at each override and a restored baseline render after reset. The reset cases show that `ESC ] 117` and `ESC ] 119` each restore only their own target, leaving the other selection color, an unrelated palette slot and the remaining overrides intact and still drawn. All four cases are supported, and every control held.
