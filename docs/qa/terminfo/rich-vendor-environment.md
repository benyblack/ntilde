# Rich TUI vendor child environment contract

The [frozen Rich TUI list](2026-11-26-rich-tui/requirements-v1.json) names four vendor environment cases. The catalogue in [the retained upstream snapshot](2026-11-15-modern-results/upstream-snapshot.zip) gives each the criterion “Manual verification required — no automated probe available.” The [pinned collector bundle](2026-11-16-shell-integration-aggregates/terminfo-dev-4.0.0.bundle.mjs.gz) has no corresponding IDs or slugs. The [stock baseline](2026-11-09-stock-baseline.json) has no grades for them.

| Frozen case | Catalogue scope and producer |
| --- | --- |
| `device.env-lc-terminal` | The case names `LC_TERMINAL` and describes the companion `LC_TERMINAL_VERSION` and the use of locale-variable forwarding over SSH. iTerm2’s session setup optionally supplies `LC_TERMINAL=iTerm2` and the bundle’s short version in `LC_TERMINAL_VERSION`. [iTerm2 session environment](https://github.com/gnachman/iTerm2/blob/f923ad5c35ae83268e6435e37f8c8b6abcf0c461/sources/PTYSession/PTYSession.m#L3711-L3714) |
| `device.env-kitty` | The case names `KITTY_PID`, `KITTY_WINDOW_ID`, and `KITTY_INSTALLATION_DIR`. Kitty supplies its process ID, the Kitty window identifier used by its remote control commands, and its installation directory. Kitty documents the native OS window ID separately as `WINDOWID`. [Kitty child environment](https://sw.kovidgoyal.net/kitty/glossary/#variables-that-kitty-sets-when-running-child-programs) |
| `device.env-wezterm` | The case names `WEZTERM_PANE` and `WEZTERM_EXECUTABLE` and describes the configuration directory and CLI socket. WezTerm sets the numeric pane ID, executable path, its companion `WEZTERM_EXECUTABLE_DIR`, `WEZTERM_CONFIG_DIR` when available, and `WEZTERM_UNIX_SOCKET` where the socket is available. [WezTerm executable bootstrap](https://github.com/wezterm/wezterm/blob/1026152aa1e6ed6f98e6dc73eda2a98a5c0ef575/env-bootstrap/src/lib.rs#L5-L12) · [WezTerm config directory](https://github.com/wezterm/wezterm/blob/1026152aa1e6ed6f98e6dc73eda2a98a5c0ef575/config/src/config.rs#L1148-L1157) · [WezTerm pane launch](https://github.com/wezterm/wezterm/blob/1026152aa1e6ed6f98e6dc73eda2a98a5c0ef575/mux/src/domain.rs#L476-L482) · [WezTerm CLI discovery](https://wezterm.org/cli/cli/index.html) |
| `device.env-wt-session` | The case names `WT_SESSION` and describes `WT_PROFILE_ID`. Windows Terminal’s ConPTY connection supplies the session GUID without braces and the profile GUID with braces. [Windows Terminal child environment](https://github.com/microsoft/terminal/blob/9a8127f201b7ef2c38e32280b9a72bf35db53d00/src/cascadia/TerminalConnection/ConptyConnection.cpp#L57-L64) |

The collector observes the 12 vendor names in the table and two independent controls. Both disposable direct-local profiles use the same App binaries and pre-shell Node fixture. The clean launch removes all vendor names and `TERM_PROGRAM`. The seeded launch provides a distinct synthetic value for every vendor name and for `TERM_PROGRAM`. Each launch also sets a different neutral `NTILDE_QA_ENVIRONMENT_CONTROL` sentinel. Shell integration, session persistence, and Node preloads are disabled for both profiles.

The owner records the allowlisted App inputs. The worker captures those same names from its own environment before fixture I/O. Each sample records absent, empty or nonempty state and the exact value. A matching parent sentinel establishes inheritance. A value arriving after the owner removed its key establishes provision on the measured launch path. An absent child key after seeding indicates filtering somewhere on that path. The App identity control requires `TERM_PROGRAM=Ntilde` in both children, and the neutral control requires both their exact sentinels.

The per-ID decision is **not applicable to Ntilde as a vendor producer** when every key in the family is absent in the clean child and inherited exactly by the seeded child. A different result requires investigation of the local launch path. The frozen criterion and stock status remain in the report. Inherited strings carry no proof that the observed terminal produces a vendor feature or owns a vendor pane, socket, process or profile. The experiment covers the measured macOS direct-local PTY path. SSH forwarding, shells, remote profiles, multiplexer sessions and other App platforms are outside its scope.

The receipt follows the [Modern child-environment collector](modern-child-environment.md). It binds both direct process relationships and the isolated pane, checks the executable and PTY binary identities, verifies terminal restoration and fixture cleanup, and retains the measured source graph. Offline replay also requires the shared desktop lock’s acquisition, cleanup and release events for each run.
