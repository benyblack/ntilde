# Owned App-private clipboard collection

The owned macOS adapter adds a seventeenth, separate private-storage report.
This implementation has deterministic synthetic and private-PTY tests; a fresh
announced disposable-App collection is still required before runtime qualification.
It does not qualify OS clipboard interchange, native clipboard reads, OSC 5522
grants, Linux desktop collection, or Windows desktop execution.

## Source and launch boundary

The BCL bootstrap captures the fixed **103-input policy v5** before importing the
runner: 82 Node/JSON inputs and 21 explicitly mapped App/VT C# reference files.
The C# aliases in `privateClipboardReferencePaths` are selected observational
inputs, not the full App dependency closure and not binary-to-source attestation.
The independently recorded executable/assembly hashes and operator version retain
that limit. The pinned, zero-dependency import scanner is unchanged.
The frozen 51/52-input v8, 60-input v9, 67-input v10 and 74-input v11 maps,
publication bytes, model expectations and original grades remain independent.

Only the newly launched process receives both matching ownership and
`--ntilde-terminfo-private-clipboard=<runId>` flags plus private settings/root/run
identities. Its effective OSC 52 write setting is enabled solely inside that
private process, where existing App startup guards disable native clipboard
providers. The fixture accepts armed synthetic nonce values only. Empty OSC 52
read denial and ordinary OSC 5522 session permission behavior are unchanged.
The ordinary collector adaptation and inline default path still send no OSC 52.

The original `aa5f2bf9956fb16870b581157e6bac8c5f11242d6eeee7975be1d92b61d5e1f6`
upstream bundle is retained separately. Private derivation inserts only an
awaited parent preparation before the original callback's synchronous OSC 52
write. Original UUID nonces, packets, cursor query and grader are preserved.
The finalizer reproduces the complete derived bundle from that pinned original
and retained source-root paths rather than trusting a derived digest alone.

## Parent transaction and independent controls

The fixed Q11 tail is roundtrip, write, then read. Fixture begin is lazy at its
first callback, after the prior query fixture is sealed and restored; earlier
RIS cases cannot silently invalidate an already active clipboard fixture.
Authenticated owner frames drive a parent-owned controller. The child gets no
arbitrary App method, fixture RPC or clipboard value capability.

Each of the 22 App RPCs has its own frozen deadline inside the owner's shared
four-second budget. A later request or abort cannot renew an in-flight event.
A dedicated 64-read observer takes 44 before/after full exposed-state snapshots,
with independent ownership checks on both sides of every capture. It preserves
attributes, stored cells, cursor state, exposed buffer state and margins.
Reverse-video memory and hidden parser/session state are not exposed or claimed.

Fresh checks include the original App/worker lineage, UID, exact executable,
private run markers, PTY and device identity, source/input hashes and binary
hashes. UTC/C-locale `ps lstart` is additional second-resolution corroboration;
it is not immutable PID identity, an atomic PTY lease or reconnect authority.
The private endpoint and singleton visible pane/profile are independently read
before and after each action. Lost/changed facts, partial controls, unconsumed
promises, duplicate callbacks, stale leases, restore failures and incomplete
close remain fatal rather than becoming an unavailable marker or a retry.

Only the fixed seed and source-known fresh nonce values enter the journal.
Callback results are admitted as provisional expected-only objects; the original
object returns to the stock grader only after the parent independently restores
and reads back the seed. Final raw traces must corroborate every original packet,
CPR, canonical empty-denial reply, callback result, observation and assertion.
The original callback passes therefore remain **false, true, false**. Private
storage restoration and two accepted writes are separate facts, not native
interchange support. `collector.ntildePrivateClipboard` is a distinct summary;
`collector.clipboardFixture` and `target.permissions` are not impersonated.

## PTY handoff and cleanup

The parent records the kernel's original `stty -g` before the worker creates any
raw fence. Owned `-opost` persists through the original pinned stock
`withRawMode`/`withTTYOperation` entry and exit and the final private close.
The old fence retires its reader without restoring modes; no reader can revive
that retired lease. Final cleanup independently attempts output, input and exact
original kernel-mode restoration, retaining original and cleanup failures.

On Darwin, restoring canonical mode can set the kernel's PENDIN reprocessing bit.
Only an otherwise byte-identical mode token with precisely that previously-clear
bit permits one nonblocking read on a new no-follow/no-controlling-terminal PTY
descriptor whose device identity equals stdin. Zero/EAGAIN is allowed; unexpected
input is fatal and its contents are never retained. The descriptor is always
closed; inherited descriptor flags are not changed. Final worker and independent
parent readback must still equal the original complete token exactly. There is
no normalized receipt, extra terminal query or input-content qualification.

The complete **schema 12** receipt rederives all 17 reports, original Q11 raw
traces, controller sequence, selected source closure and exact restoration, then
requires App/worker cleanup, fixture removal and captured-source removal.
A private declaration, import, source alias, partial journal or summary cannot
be coherently stripped into a schema 11 receipt. Typed earlier unavailable
reports remain historical facts; a started private fixture has no unavailable
escape hatch.

Run the `private_clipboard_owned` Node 24 CI command for synthetic controls and
full-receipt refusals. Ubuntu and Windows jobs gate the normal required rollup;
they are not desktop qualification. The real private-PTY transport test in
`terminal-output.test.mjs` runs on macOS without an App or OS clipboard.
Only the coordinating operator may announce and launch a genuine GUI collection.
