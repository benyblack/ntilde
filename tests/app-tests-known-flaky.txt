# Tests in the headless App.Tests lane that are allowed to fail without failing the job.
# Enforced by scripts/check-app-tests-baseline.py; anything failing that is NOT listed here
# fails the "Unit Tests" job, and so does a hang.
#
# The lane's test steps run continue-on-error so that this list, rather than `dotnet test`'s
# exit code, decides whether a failure blocks - that is the only reason they still do. They
# once also tolerated the #81 teardown hang, and that tolerance made every result invisible:
# the job was green for weeks while 16 tests failed on Windows and 14 on ubuntu. Naming each
# accepted failure is what keeps the choice deliberate.
#
# Rules for adding a line:
#   - Only genuine non-determinism (timing, ordering, environment). A test that is simply
#     broken belongs fixed, not listed.
#   - Say what makes it flaky and what would make it deterministic.
#   - Matching is by substring, so a name without theory arguments covers every case.
#   - Removing a line is always in scope. Growing the list is a decision, not a chore.
